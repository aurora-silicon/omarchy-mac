# Build contracts

Build as an unprivileged user in a disposable, signed Arch/ALARM dependency root. Use the exact package database/archive locks selected by assembly. Do not replace dependencies with arbitrary installed libraries. Keep generated build directories outside the public source tree; guards reject modified, untracked and ignored files that could inject inputs. Normal SOURCE_DATE_EPOCH and compiler identity belong in receipts, not a claim of bit reproducibility.

## Runtime and ordinary userspace

The a761 runtime/settings pair uses pinned Git by default. `OMARCHY_SRC` is optional; when used it must point at a clean exact a761 checkout. The same HEAD/clean-tree guard checks either route. The normal package-release difference (-2 runtime/-6 settings) is intentional. Git checksum SKIP is paired with exact commit/tree guards; no stale c668 checksum is advertised for a761.

Run makepkg --cleanbuild for the individual runtime, speaker, audio, libfprint, UPower, GTK2, Xwayland, userpages and Steam source recipes with their declared dependencies. Speaker's default compiles public d6ee942 directly; the old unqualified HEAD-only cached binary shortcut is absent. UCM and asahi-audio are separate from speaker compilation, so rebuilding their profiles does not pull an obsolete speaker patch. Native and guest Mesa recipes fetch public524 and pinned upstream wrap archives, then configure with no Meson downloads. Preserve their inherited licenses and maintainers.

The normal SEP tools package should be consumed from immutable public Linux5d38582b13215e4e5df796bb8a6967f6a38c2d61b13215e4e5df796bb8a6967f6a38c2d61 (or its later explicitly reviewed source). Its package owns the alias-only blacklist/first-load behavior. Omarchy-specific firmware ordering and initrd inclusion use the existing installer pipeline; do not restore the rejected activation-approved or per-install signed-approval proposals. The source bundle does not enable services or modify PAM on this workstation.

## FEX clean source route

Use a native aarch64 Arch build environment providing LLVM/Clang22 (including libclang/LLVM CMake packages), declared GUI/native libraries, CMake, Ninja and NASM. Native LLVM23 failed this source's thunk-generator API; do not silently substitute it. Guest compile/toolchain tests are real and are never forced successful.

```sh
cd recipes/fex
makepkg --cleanbuild --syncdeps
```

prepare verifies public FEX14c commit/tree and locked source-only submodules, downloads and checksum-checks every development RPM, extracts a separate dual-ABI sysroot and normalizes absolute guest symlinks to that root. It never executes guest RPM scriptlets. build configures native host plus32/64-bit guest thunks using the retained successful LLVM22 flags/toolchains; all build outputs are outside the source checkout. package installs the result and individually checked upstream license notices, including distinct embedded SoftFloat BSD notices from pinned Git blobs. The older package attempted a nonexistent SoftFloat COPYING file; its notice correction must be repacked with new receipts rather than relabeled. Binary-test submodule inputs are not fetched by the source-only lock.

`FEX_DEVEL_CACHE` may point at a cache of the exact public RPMs; every byte is hashed before use. No private controller path or preconfigured CMake cache is required. Signature metadata and hash qualification are separate facts; see the final public-fetch qualification receipt supplied by root. Do not describe an issuer key ID as full cryptographic signature verification.

For optional reuse, first publish and qualify the exact reviewed FEX archive at an immutable HTTPS URI, fill that URI in reuse.lock.json, and regenerate the support checksum in PKGBUILD. `FEX_REUSE_ARCHIVE` may then name a downloaded copy. Its fixed public source identity and SHA256 are verified twice before extraction; package metadata is regenerated by makepkg. The initial URI is intentionally unset, so a private artifact cannot masquerade as an admitted public reuse input. Do not set an arbitrary hash just to accept a local binary.

## Guest Mesa correction

Use an x86_64 Arch build environment and the declared32-bit development closure. The cross_x86 file is a source-declared, checksum-pinned input in srcdir. Native ARM64 Mesa is built independently. Only the overlay packages belong on the host; mesa-dummy is guest-only.

The ordinary recipe builds clean. ## Kernel clean source route

Use a native aarch64 Linux environment, public Linux 5f6c917f2c824b3c87497e8bd7dd92a6de0efe60, the included exact config, Rust1.97.1, LLVM/Clang22 and bindgen0.73.2 with matching libclang. The current incremental module used those inputs. This bundle does not contain them as opaque binaries; install/build those public toolchain versions through their normal sources.

```sh
mkdir linux-source
git -C linux-source init
git -C linux-source remote add origin https://github.com/aurora-silicon/linux.git
git -C linux-source fetch --depth=1 origin 5f6c917f2c824b3c87497e8bd7dd92a6de0efe60
git -C linux-source checkout --detach FETCH_HEAD
mkdir linux-build
cp recipes/kernel/config linux-build/.config
export ARCH=arm64 LLVM=1 RUSTUP_TOOLCHAIN=1.97.1
export KCFLAGS=-Werror KRUSTFLAGS=-Dwarnings LOCALVERSION=''
export SOURCE_DATE_EPOCH=1791939600
export KBUILD_BUILD_TIMESTAMP='2026-10-14 01:00:00 +0000'
export KBUILD_BUILD_USER=builder KBUILD_BUILD_HOST=production KBUILD_BUILD_VERSION=1
make -C linux-source O="$PWD/linux-build" BINDGEN=bindgen olddefconfig
cmp recipes/kernel/config linux-build/.config
make -C linux-source O="$PWD/linux-build" BINDGEN=bindgen -j10 Image modules dtbs
python3 scripts/stage-kernel-inputs.py linux-source linux-build clean-kernel-inputs
```

Staging creates local build-input archives/config/license/receipts only; it never installs to the live system or loads a module. It checks the exact public source, unchanged effective config, complete113-DTB roster and native AArch64 header helpers. Staging emits ready-to-makepkg kernel/header recipe directories with checksums derived from those actual new outputs. Run makepkg inside each generated directory; no hand-editing public reuse hashes or recipe checksums is required. Those generated recipes explicitly identify new clean-source outputs, distinct from the immutable old reuse route. The kernel recipe accepts an actual clean 5f6 compile receipt as well as the retained qualified incremental 5f6 receipt. External C module rebuild tests remain mandatory for new header outputs; Rust external modules additionally require matching generated Rust metadata and are not qualified here.

Current delivered artifacts use an exact-public-source incremental 5f6 build from the recorded cd46 cache: SEP and the built-in PMGR driver were rebuilt, the Image was relinked and the J700 DTB changed; all113 Apple DTBs are packaged and112 are unchanged. The package recipe preserves that actual identity instead of calling it a new clean build. To reproduce those existing bytes by reuse, publish the frozen runtime/header input archives and receipts with the exact hashes/URLs in public-reuse-assets.json and materialize them with scripts/fetch-reuse.py. Private cache directories alone are not a public reproduction route. Headers keep their original native-helper source/reuse identity; a source-only schema delta is not a reason to fabricate a fresh compile claim.

All fresh compiler/metadata routes above are source-normalized and fixture-checked, not full-rebuilt by this task. Root/native workers own actual archive qualification and publication. The source recipe bundle cannot replace dependency, firmware, initrd/UKI, installation or physical qualification.
